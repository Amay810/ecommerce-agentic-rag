混合检索 — 为什么 dense alone 不够
🔵 Dense（语义）
  • paraphrase-multilingual-MiniLM-L12-v2
  • 余弦相似度闸门 0.35
  • 擅长：口语问题、同义改写
  • 弱点：型号数字退化为随机位置
🟡 BM25（词法）
  • jieba 分词
  • IDF 权重对精确匹配极敏感
  • 擅长："H900"、"3000mAh"、型号
  • "H900" 不在训练语料 → dense 无效
⚡ RRF 融合 + 父子文档
  • RRF：1/(k+rank) 加权，排名融合避免相似度绝对值不可比
  • 无需调 scale 参数，对分布差异鲁棒
  • 父子文档：检索细粒度子 chunk（desc/attr/qa/review）
  • 喂 LLM 完整父卡，保留上下文（关键细节跨 chunk 时不丢失）

生成后验证 — 三层可信度闸门
① 句级 Grounding
encode(回答句) ↔ encode(context 句)
余弦相似度 > 0.42 = 有支撑  ·  <50% 支撑率 → caution
② 数字引用检查
regex 检测回答中的价格/规格数字，验证是否有 [资料N] 标注
无引用数字 → caution
③ LLM 一致性检查
判断回答是否"矛盾 / 资料外 / 通过"（有 API key 时启用）
矛盾 → 直接 handoff
三层 → final_decision(grounding, consistency, citation) → ok / caution / handoff
回答不是生成完就给用户，要先过可信度闸门。
💬 面试钩子
"grounding 阈值 0.42 怎么定的？" → 在 eval 集上调参，过低则 caution 率过高（用户体验差），过高则错放幻觉回答。0.42 是在 28 题上 caution_rate 和 accuracy 的 tradeoff 点。

FailureMemory — 定位真正瓶颈，不靠直觉
累积 SupportCase → FailureMemory.analyze() 自动挖掘模式，直接产出修复优先级：
Pattern根因诊断产出修复目标

stale_data_caution KB 文档 updated_at 超期 freshness guardrail
FM vs CM 的分工
  • FailureMemory：离线 batch 分析，pattern detection，输出修复方向
  • CaseMemory：在线 advisory，query-time 语义检索，输出先验 trace
  • 一个诊断，一个预防
其余 pattern（备注）
  • zero_retrieval_handoff
  • handoff_cluster
  • KB 缺口：retrieval_blind_spot、stale_doc
FailureMemory 不是日志，是修复优先级生成器；不靠直觉猜哪里坏。
💬 面试钩子
"FailureMemory 和 CaseMemory 有什么区别？" → FM 是离线分析（batch pattern detection），CM 是在线 advisory（query-time semantic match）；一个诊断，一个预防。FM 的输出是"该修哪里"，CM 的输出是"这道题历史上有没有类似失败，给个 hint"。

两个精准修复 — 针对 embedding 的已测失效模式
Q3 — 价格约束过滤
  • 根因：embedding "预算600以内" 仍把 P009@899元 排名第一
    数值约束 ≠ 语义相似度问题
  • 修复：price_filter.parse_budget() 解析中文预算表达
    → post-retrieval 过滤 price > budget
  • 结果：Q3 recall@1：0 → 1
Q28 — 复合查询分解
  • 根因："保温杯"子查询返回 P014（P014 Q&A 含"和普通保温杯有什么不同"→语义污染）
  • 修复：detect("A和B") → 分别检索各子实体 + 全量 query → doc级 RRF → 标题 bigram 保底注入
  • 英文护栏："RunBuds Clip 和 Air Pro 2" 不截断（\s 不作 stop char；纯 CJK 才限 8 字符）
  • 结果：Q28 recall@5：0.5 → 1.0（P006 进入候选池）
这些不是拍脑袋规则，而是由 gold-doc evaluation 和 FailureMemory 定位出的确定性修复层—— 针对 embedding 的已测失效模式，可解释、可测试、可回滚。
知道 embedding 在哪里失效，才知道用什么规则补它。
💬 面试钩子
"为什么不直接微调 embedding 模型来理解价格约束？" → 微调需要带 price 标注的对比训练对，成本高、泛化性差；rule-based filter 可解释、可测试、可回滚。
"标题 bigram 保底会不会误命中？" → 中文实体要求≥2 CJK；英文走 token overlap；多命中按分数排序。设计有三道 guardrail。
