# 简历与面试表述

## 推荐简历三条

- 基于 Qwen3-4B 构建多轮电商工具型 Agent，由模型根据对话和工具 observation 自主选择商品检索、政策查询、订单操作、用户确认或转人工等下一行动，并保存完整可重放轨迹。
- 设计 8 类 typed tools 与身份验证、业务资格、显式确认三层事务 guardrail，通过数据库终态检查验证高风险操作；在 120 个任务、360 条真实 LLM 轨迹中将非法状态变更率保持为 0。
- 为 Agent 接入面向 5,000 商品、43,953 文本块的 Dense + BM25 + RRF 事实检索，并建立覆盖 action selection、工具契约、策略合规、轨迹回放和数据库终态的分层评测体系。

## 面试时主动说明

- 5k scale set Recall@5=0.992、P95=126ms；它不等于模糊自然语言能力，独立困难集 Recall@5=0.689。
- 360 条中的 84.17% 是自动化操作指标，不含最终回答完整性、事实忠实度和推荐质量的全面判断。
- 40 条审核采用排序后固定步长抽样，不是随机总体样本。
- Guardrail 令非法状态变更为 0，不代表 Agent 决策完全合规：5% 的轨迹仍尝试了禁止工具。
- RL gate 未通过；项目没有宣称 DPO、PPO、GRPO 或 Agent RL。
- terminal-grounding v2 的事实通过率差值为 0，结论是 `negative_or_inconclusive`。

## 不使用的表述

- 不将 RAG 写成项目主语；它是 Agent 的动态事实获取机制。
- 不把旧评分器的 94.17% 称为人工验证成功率。
- 不把 guardrail 阻断写操作称为 Agent 策略 100% 合规。
- 不把确定性三次重复解释为独立随机试验的 pass³。
